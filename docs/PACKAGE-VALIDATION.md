# Public package validation

Validation performed on 2026-10-12 on macOS with uv-managed CPython 3.14.6. These checks created temporary fixtures and compiled source. They did not execute a public runtime installer inside Lightroom, start the helper, enable a LaunchAgent, open a catalog database, or publish a repository.

| Check | Result | What it establishes |
|---|---|---|
| Python compilation and eight unit tests | Passed | SQLite affinity/type counterexample, source-pin closure, rendered local-source existence, temporary installation with unchanged catalog fixture, overwrite refusal, callback classification, foreign LaunchAgent ownership, altered startup configuration held before enablement |
| Rendered Lua parser | 19 runtime Lua sources and the separate folder adapter passed; four changed sources and three embedded native request payloads rechecked | Syntactic validity after path and dependency-hash substitution; no native API acceptance |
| AppleScript compilation | Both rendered sources passed `osacompile` | macOS compiler acceptance; no permission or menu-dispatch proof |
| Temporary stage installation | Passed; automation remained disabled | Configurable paths, complete dependency rendering, byte pins and refusal to overwrite existing output |
| Public content review | No catalog, media, personal paths, Cloud catalog IDs or decompiled Adobe module bodies included | Finite reviewed source scope; runtime logs remain private local evidence |

Reproduce the automated package checks from the repository root:

```sh
uv run --no-project python -m py_compile scripts/manage.py
uv run --no-project python -m unittest discover -s tests -v
```

`templates/SOURCE-PINS.json` records SHA-256 provenance for our authored installed predecessors. Rendering rebinds their dependency hashes to the generated bytes until the complete dependency closure stabilizes. The source pins are provenance, not an assertion that a newly generated package has already run. Adobe implementation modules are imported from the user's installed application at runtime.

The source-existence test checks all twenty packaged dependencies against a physical staged tree, including embedded native request text, resolvable local-prefix concatenations, digest source literals and the helper's dispatch source. It also checks that every runtime Lua/SQL dependency's generated byte hash occurs in the rendered native pin closure. Deliberately removing a dependency fails the test even when rendering, hashes and syntax remain valid. Runtime receipt/ACK/log files are created during execution, and the external Adobe date module remains an application dependency. Generated transport jobs use the same checked templates; their eventual native ownership and callback effects still require actual runtime proof.

Phase 1 now checks the authored map/count Lua and journal SQL hashes before loading/reading them, including manual menu invocation. Reverse transport checks its authored codec hash in the native request and includes that codec in the controller's dependency pins. These are specific checked paths; interpreter compilation and source pins do not replace actual native acceptance.

The generated `startup.plist` belongs to the byte-pinned manifest. Verification also requires the exact configuration-derived Label, interpreter/uv/owned-script arguments and launch configuration before enablement. The negative test changes its arguments and proves that verification fails with no LaunchAgent or `launchctl` action; it also rejects a foreign command even after its manifest hash is rewritten.

Public restoration guards additionally bind the exact currently owned map/count and tracking wrappers before replacement. The map/count guard retains all nine actual installed TEMP definitions and rechecks their names, types, owning tables and SQL before transactional cleanup. A foreign method, global owner or definition leaves an explicit held state with its ownership and TEMP objects retained; old wrapper aliases fall back to the native query. These source changes passed parsing and were submitted for independent review; their new restoration/cleanup paths have not been exercised in a public native Lightroom session.

Public generalizations include configured paths, an explicitly configured catalog, current native Cloud-group lookup, twenty dynamically selected legitimate file scopes for affinity comparisons, and owned enable/pause markers. The complete numeric/integral metadata-key gate and selected-pair equality remain required. Affinity and the durable expression index remain disabled by default.

The folder adapter is an explicit example, not a startup phase or a durable repair coordinator. A caller must bind fresh current native ownership, the full preservation snapshots, the exact reviewed plan and committed-batch journal. Its attempted state prevents replay of that same in-memory plan; it does not manufacture a durable recovery receipt.

Native qualification still requires the manual callback and all seven phase receipts, then separate transport startup, native oracle, normal restart, cleanup and later renewal observations. Disabled phase receipts do not qualify the affinity or schema changes. Follow the [README](../README.md) and preserve actual failed receipts rather than weakening gates or repeating completed work.
